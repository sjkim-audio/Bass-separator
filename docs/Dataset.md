# Dataset Documentation

본 문서는 베이스 음원 분리 알고리즘의 성능 평가 및 향후 모델 파인튜닝(Fine-tuning)을 위해 직접 녹음 및 구축한 커스텀 데이터셋의 명세와 설계 목적을 기록합니다.

---

## 1. Evaluation Dataset (현재 성능 평가용 데이터)

모델의 베이스 분리 성능을 주법 및 음역대별로 정밀하게 검증하기 위해 통제된 환경에서 제작된 베이스라인 테스트 음원입니다.

* **파일명**: `performance_test_demo(guitar + bass).wav`
* **길이**: 약 1분
* **트랙 구성**: 일렉트릭 기타 1 트랙 + 일렉트릭 베이스 1 트랙 (총 2 트랙)
* **음향적 특징**: 별도의 이펙팅(앰프 시뮬레이터, 드라이브, 공간계 등)을 거치지 않은 순수 DI(Direct Injection) 소스(Raw Recording)입니다.

### 1.1 음악적 구성 및 편곡 특징
* **코드 진행**: C Major 키(Key) 기준 `II - V - I - VI` (Dm7 - G7 - Cmaj7 - Am7) 진행을 따릅니다.
* **일렉트릭 기타 (Backing)**: 코드 반주(Comping) 위주로 연주되며, 하나의 코드 사이클마다 동일한 연주 소스가 반복됩니다. 이를 통해 배경음(기타)을 상수로 통제하고, 베이스 연주 변화에 따른 모델의 분리 성능을 정확히 측정할 수 있습니다.
* **일렉트릭 베이스 (Main Target)**: 두 프레이즈(코드 2바퀴) 단위로 연주 주법과 포지션이 지속적으로 변화하며, 총 4개의 섹션으로 구성됩니다.
  1. **Root Notes**: 근음 위주의 단순 연주 (저음역대 보존력 테스트)
  2. **Standard Line**: 코드톤과 스케일을 활용한 일반적인 베이스 라인 (다이내믹 및 선율 인식 테스트)
  3. **High-register Solo**: 12프렛 부근에서 연주되는 고음역대 솔로 라인 (기타 주파수와의 간섭 및 블리딩 방어력 테스트)
  4. **Slap Bass**: 엄지와 검지를 활용한 슬랩 주법 (강한 어택(Attack) 성분과 고주파 배음의 분리 및 왜곡(SAR) 테스트)

### 1.2 실험 목적
단순히 악기를 분리하는 것을 넘어, **베이스의 특정 주법 및 플레이 특성(음역대, 타격감 등)에 따라 분리 모델(Demucs 등)의 성능(SDR, SIR, SAR)이 어떻게 변화하는지 정량적/정성적으로 파악**하는 것이 주 목적입니다.

## 2. Future Dataset Expansion (향후 확장 및 파인튜닝 계획)

현재의 통제된 DI 투트랙 환경에서의 평가를 마친 후, 실전 믹싱 환경에 대응하고 모델의 성능을 향상시키기 위해 다음과 같은 데이터셋 확장을 계획하고 있습니다.

### 2.1 Hard Case Testing (실전 환경 변수 추가)
* **세션 추가**: 주파수 간섭이 심한 킥 드럼(Kick Drum) 트랙 등을 추가하여 모델의 악기 간 간섭 제거(SIR) 능력을 테스트합니다.
* **이펙터 적용**: 앰프 시뮬레이터, 오버드라이브/디스토션, 공간계(Reverb/Delay) 이펙터를 걸어 배음이 왜곡되고 공간감이 추가된 상황에서의 분리 성능 저하율을 측정합니다.

### 2.2 Fine-tuning Dataset (파인튜닝 전용 데이터셋 구축)
* 위의 평가 과정에서 발견된 모델의 취약점(예: 슬랩 주법에서의 아티팩트 발생, 하이 포지션에서의 기타 블리딩 현상 등)을 집중적으로 보완할 수 있도록 타겟팅된 맞춤형 데이터셋을 새로 녹음합니다.
* 구축된 데이터를 바탕으로 Demucs 2-Stem 모델을 베이스 특화 모델로 파인튜닝하여, 최종적으로 고도화된 악보 생성 및 톤메이킹을 위한 최상급 베이스 소스를 확보할 계획입니다.

## 3. Data Augmentation Strategy (파인튜닝용 데이터 증강 전략)

Demucs 2-Stem 모델의 파인튜닝(Fine-tuning)을 위한 대규모 데이터셋 구축 시, 단순한 무작위 믹싱(Random Stem Mixing)이 유발하는 **'음악적 맥락 파괴(리듬 및 화성 불일치)'** 현상을 방지하기 위해 다음과 같은 이원화된 증강(Augmentation) 파이프라인을 설계하여 적용합니다.

### 3.1 이원화된 증강 원칙 (Bifurcated Augmentation)

**A. 전역적 증강 (Global Augmentation) : 음악적 무결성 보존**
* **대상**: 조옮김(Pitch Shift), 속도 조절(Time Stretch)
* **원리**: 분리된 개별 트랙(Bass, Other)에 각기 다른 변형을 주지 않고, **반드시 모든 트랙에 정확히 동일한 비율의 피치 및 템포 변환을 동기화(Synchronize)하여 적용**합니다.
* **목적**: 원본 DI 소스의 코드 진행과 리듬의 타격 시점(Transient)을 완벽히 보존하면서도, 다양한 키(Key)와 템포의 데이터를 확보하여 실전 방어력을 기릅니다.

**B. 독립적 증강 (Stem-specific Augmentation) : 강건성(Robustness) 확보**
* **대상**: 트랙별 믹스 볼륨(Random Gain), 톤 왜곡(Hard Clipping / Distortion)
* **원리**: 음악의 화성과 리듬을 해치지 않는 선에서 각 트랙의 음향적 특성만 무작위로 변형합니다. 특히 베이스 트랙에 일정 확률로 디스토션을 가하거나, 베이스의 볼륨을 기타보다 현저히 낮추어 믹스합니다.
* **목적**: 모델이 특정 베이스 톤에 과적합(Overfitting)되는 것을 방지하고, 베이스가 배경음에 깊게 묻혀 있는 하드 케이스(Hard Case) 환경을 모사하여 분리 성능을 극대화합니다.

### 3.2 출력 규격 및 수학적 무결성 (MusDB18 Format)

모든 증강 데이터는 음악 소스 분리 분야의 표준인 **MusDB18 데이터셋 규격**을 준수하여 렌더링됩니다.

* **구조**: `train/`, `valid/`, `test/` 디렉토리 하위에 각각의 증강 버전 폴더 생성.
* **파일 구성**: 각 폴더 내에는 `bass.wav`, `other.wav`, 그리고 `mixture.wav`가 포함됩니다.
* **무결성 보장**: 파이프라인을 통해 생성된 `mixture.wav`는 오디오 텐서 레벨에서 `bass.wav + other.wav`의 수학적 합산과 완벽히 일치하도록 설계되어, 모델의 손실 함수(Loss Function) 계산 시 위상(Phase) 오류가 발생하지 않도록 통제합니다.
