# [Architecture Document] Phase 7: Rhythmic Quantizer (리듬 양자화기) 설계안

본 문서는 자동 베이스 채보 파이프라인의 Phase 7 진입을 위한 리듬 양자화 알고리즘의 총체적 점검 및 수학적/논리적 구조를 명세한다. 본 문서는 `docs/ADR/Phase7_Quantizer_Architecture.md`로 저장하여 향후 구현의 기준으로 삼을 수 있다.

---

## 1. 개요 및 목표 (Overview & Objectives)

**목표:** 피치 트래킹(Phase 6) 단계에서 도출된 밀리초(ms) 단위의 물리적 시간 데이터를 음악적 박자(Grid)에 맞게 정규화(Normalize)하여, 타브 악보 및 MIDI 렌더링 시 발생하는 충돌, 노이즈, 가독성 붕괴를 해결한다.

**핵심 해결 과제:**
1. 노트 시작점(Onset) 및 지속 시간(Duration)의 동시 양자화
2. 파편화된 노이즈 노트의 논리적 병합(Merge) 및 필터링(Drop)
3. 가변 템포(Dynamic Tempo) 및 복합 리듬(3연음, 스윙) 대응

---

## 2. 핵심 알고리즘 선택 이유 및 트레이드오프 (Trade-off Analysis)

### 2.1. 단선율(Monophonic) 강제화 vs. 다성음(Polyphony) 허용
* **결정 사항:** 철저한 **단선율 강제화(Monophonic Enforcement)** 채택.
* **이유:** 현재 파이프라인의 코어 피치 추정기(CREPE)는 근본적으로 단선율 기반이다. 베이스 기타의 저음역대 배음 간섭으로 인해 발생하는 다중 피치를 화음으로 인정할 경우 위양성(False Positive)이 기하급수적으로 증가하며, ASCII 타브 악보 상에 다성음을 세로로 정렬하는 렌더링 비용이 지나치게 높다.
* **트레이드오프:**
    | 비교 항목 | 단선율 강제화 (선택) | 다성음 허용 (기각) |
    | :--- | :--- | :--- |
    | **정확도 (노이즈)** | 배음/노이즈에 의한 가짜 화음 완벽 제거 | 가짜 화음 난입으로 악보 가독성 심각한 훼손 |
    | **구현 복잡도** | 단순한 선형 시계열 처리 (시간축 충돌만 보정) | MPE 모델 교체 필요, 2차원 텍스트 렌더링 복잡도 극상 |
    | **표현력 상실** | 의도된 더블 스탑, 코드 스트로크, 동시 타현 누락 | 모든 물리적 연주 뉘앙스 보존 (이론상) |

### 2.2. 동적 템포 맵(Dynamic Tempo Map) vs. 정적 단일 BPM
* **결정 사항:** Demucs의 드럼(Drum) 스템을 활용한 **동적 템포 맵 추출** 채택.
* **이유:** 실제 사람이 연주한 곡(특히 밴드 음악)은 미세하게 템포가 변동한다(Tempo Rubato). 곡 전체를 단일 BPM으로 양자화하면 곡 후반부로 갈수록 격자가 완전히 어긋나는 누적 오차가 발생한다. 드럼 스템의 어택을 기반으로 비트 타임스탬프 배열을 구성하여 마디별 로컬 격자를 생성해야 한다.

### 2.3. 다중 격자 오차 최소화 (Multi-Grid Error Minimization)
* **결정 사항:** 16분음표 격자와 3연음(12/24분음표) 격자를 동시 계산하여 오차가 적은 격자를 마디 단위로 동적 선택.
* **이유:** 베이스 라인에는 스트레이트 리듬과 셔플/스윙, 3연음 필인(Fill-in)이 혼재될 수 있다. 16분음표 격자 하나만 강제할 경우 3연음 오프비트가 오조준되어 심각한 위상 왜곡(플램)이 발생한다.

## 3. 수학적 모델 및 논리 구조 (Mathematical Models & Logic)

### 3.1. 템포 맵 기반 동적 격자 연산 (Dynamic Grid Calculation)
드럼 스템에서 추출한 비트 배열 B = [t_1, t_2, ..., t_k] 가 존재할 때, 임의의 k번째 비트와 k+1번째 비트 사이의 구간(1박자)에 대한 해상도 N(예: 16분음표 = 4분할, 3연음 = 3분할)의 격자 간격 Δg_k 는 다음과 같이 정의된다.

Δg_k = (t_{k+1} - t_k) / N_subdivision

### 3.2. 다중 격자 손실 함수 (Multi-Grid Loss Function)
특정 마디(Measure) 내에 포함된 모든 노트의 원본 시작 시간 집합을 O 라고 할 때, 특정 격자계 G(스트레이트 또는 3연음)에 스냅(Snap)했을 때 발생하는 양자화 오차의 평균제곱오차(MSE)를 계산한다.

Loss(G) = (1 / |O|) * Σ (O_i - Snap(O_i, G))^2

알고리즘은 Loss(G_straight) 와 Loss(G_triplet) 를 비교하여 값이 최소가 되는 G_opt 를 해당 마디의 전역 격자로 채택한다.

### 3.3. 지속 시간(Duration) 양자화 및 충돌 보정
노트 i의 양자화된 시작점을 O'_i, 종료점을 E'_i 라고 할 때, 오버랩을 방지하고 단선율을 강제하기 위한 보정 로직은 다음과 같다.

1.  **초기 스냅:** E'_i = Snap(E_i, G_opt)
2.  **최소 지속시간 보장 (Minimum Duration):** 양자화 직후 길이가 0이 되거나 너무 짧아지는 것을 방지한다.
    If (E'_i - O'_i) < Δg_opt, then E'_i = O'_i + Δg_opt
3.  **충돌/오버랩 제거 (Collision Resolution):** 다음 노트 i+1 의 시작점을 침범하는 경우 단절시킨다. (δ는 시각적 여백을 위한 극소값)
    If E'_i > O'_{i+1}, then E'_i = O'_{i+1} - δ

## 4. 잠재적 결함 및 한계점 (Flaws, Limitations & Edge Cases)

제안된 아키텍처를 도입할 때 발생할 수 있는 명확한 한계점들은 다음과 같다. 철저히 인지하고 파이프라인 운영 시 주의해야 한다.

1.  **복합 리듬(Polyrhythm) 및 혼합 릭(Mixed Lick) 훼손:**
    * **한계:** 다중 격자 오차 최소화 알고리즘은 **'마디 단위(Measure-level)'**로 최적 격자를 선택한다. 만약 한 마디의 전반부는 정확한 16분음표 스트레이트이고, 후반부는 8분 3연음으로 연주되었다면, 알고리즘은 오차 합계가 더 작은 쪽의 단일 격자로 마디 전체를 덮어씌운다. 이는 원본 리듬의 미세한 뉘앙스를 심각하게 훼손할 수 있다.
2.  **드럼 부재 구간에서의 템포 맵 붕괴:**
    * **한계:** 베이스 솔로, 드럼이 쉬는 브레이크다운(Breakdown), 페르마타(Fermata) 구간에서는 비트 트래킹 알고리즘이 기준점(어택)을 잃고 난수를 뱉거나 비트를 놓칠 수 있다. 이 구간에서는 양자화 격자가 폭주하여 노트들이 비정상적으로 길어지거나 짧아지는 엣지 케이스가 발생한다.
3.  **의도된 스타카토와 데드 노트(Dead Note)의 소실:**
    * **한계:** 최소 지속시간 보장(Minimum Duration) 로직에 의해, 의도적으로 짧게 끊어 친 16분음표 이하의 쨉(Jab)이나 고스트 노트들이 강제로 지정된 격자 길이(Δg)만큼 늘어난다. 이는 그루브를 둔탁하게 만드는 원인이 된다.
