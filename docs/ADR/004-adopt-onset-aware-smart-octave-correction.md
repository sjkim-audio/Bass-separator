# [ADR-0004] Onset 탐지 기반의 스마트 옥타브 보정 및 파이프라인 재배치

* **Status:** Accepted
* **Date:** 2026-03-03
* **Category:** Core Algorithm / DSP Post-processing

## 1. Context (배경)

Phase 2에서 피치 트래커로 딥러닝 모델(CREPE)을 도입하여 전반적인 인식률은 크게 향상되었으나, 베이스 기타 특유의 두꺼운 배음(Harmonics) 구조로 인해 지속음(Sustain) 구간에서 피치가 갑자기 1옥타브(±12 Semitones) 위로 튀는 **옥타브 에러(Octave Error)**가 간헐적으로 발생했다. 

이를 해결하기 위해 초기에는 단순 이동 중앙값(Rolling Median) 필터와 기계적인 옥타브 차감(Diff 12) 로직을 적용했으나, 다음과 같은 두 가지 치명적인 부작용이 발견되었다.

1.  **음악적 의도 훼손 (False Positive):** 베이스 연주에서 1옥타브 도약은 슬랩 앤 팝(Slap & Pop)이나 디스코 베이스라인 등에서 매우 빈번하게 쓰이는 **의도된 연주 기법**이다. 기존의 기계적 보정 로직은 이러한 정상적인 연주까지 에러로 간주하여 강제로 평탄화(Flatten)해버리는 심각한 왜곡을 낳았다.
2.  **NaN 전파 (NaN Propagation):** 모델의 신뢰도(Confidence)가 낮은 구간을 너무 이른 단계에서 결측치(`NaN`)로 마스킹 처리함에 따라, 이후 수행되는 Rolling Median 연산 윈도우에 `NaN`이 포함될 경우 전체 결과값이 연쇄적으로 `NaN`으로 오염되는 데이터 소실 현상이 발생했다.

## 2. Decision (결정)

음악적 도메인 지식과 신호 처리 파이프라인의 안전성을 결합하여, 다음과 같이 후처리(Post-processing) 로직을 전면 개편한다.

1.  **파이프라인 재배치 (Reordering):** 신뢰도 기반의 `NaN` 마스킹 작업을 스파이크 제거(Median Filter) 및 옥타브 보정 연산이 모두 끝난 **가장 마지막 단계로 지연(Delay)**시킨다.
2.  **스마트 옥타브 보정 (Onset-aware Correction):** `librosa.onset.onset_detect`를 활용하여 오디오 파형에서 물리적인 타격(Attack) 에너지가 급증하는 구간을 추출한다. 
    * 이동 중앙값 트렌드 대비 **±1옥타브 도약**이 발생했을 때, 해당 시점 근처(±2 프레임 허용 오차)에 **Onset(어택)이 존재한다면 이를 '의도된 연주'로 간주하여 보존**한다.
    * 반대로 **Onset이 없는 지속음 구간에서 도약이 발생했다면, 이를 딥러닝 모델의 '배음 인식 에러'로 확정 짓고 강제 보정(±12 MIDI Note)**한다.

## 3. Rationale (의사결정 근거)

### 3.1. 도메인 특화 휴리스틱 (Musical Context over Pure Math)
베이스 기타의 물리적 특성상, 새로운 줄을 튕기거나 뜯지 않고(즉, Onset 없이) 피치가 정확히 1옥타브 도약하는 것은 자연적인 연주에서 불가능에 가깝다. 반대로 강한 타격감(Onset)과 함께 옥타브가 뛰는 것은 전형적인 팝(Pop) 주법이다. 순수 수학적 필터링의 한계를 악기의 물리적, 음악적 맥락(Domain Knowledge)을 교차 검증 도구로 사용하여 완벽하게 극복할 수 있다.

### 3.2. 데이터 연속성 확보 (Preventing NaN Propagation)
Pandas의 `Rolling.median()` 함수는 윈도우 내 결측치를 무시하거나 처리하는 옵션(`min_periods`)이 있지만, 연속된 결측치 앞에서는 트렌드 추적 기능이 무너진다. `NaN` 할당을 뒤로 미루면, 다소 부정확하더라도 '연속된 숫자 데이터'가 유지되므로 스파이크성 노이즈를 중앙값으로 안전하게 깎아낼 수 있는 수학적 안정성이 확보된다.

## 4. Consequences (결과)

* **Positive:**
    * 기계적 에러(Harmonic Jumping)와 실제 연주 기법(Slap)을 완벽하게 구분해 내어 타브 악보의 신뢰도가 비약적으로 상승했다.
    * 파이프라인 순서 변경만으로 데이터 소실(NaN 오염) 버그를 메모리 추가 비용 없이 완전히 해결했다.
* **Negative (Mitigated):**
    * 옥타브 보정을 위해 원본 오디오 파형 전체를 한 번 더 스캔하여 Onset Envelope를 계산해야 하므로, 후처리 연산 시간이 소폭(약 1~2초) 증가한다.
    * **Mitigation (완화):** 피치 트래킹과 완전히 동일한 `sr` 및 `hop_length`를 사용하여 Onset 프레임 배열을 추출함으로써, 복잡한 시간축 보간(Interpolation) 연산을 생략하고 1:1 인덱스 매핑만으로 O(N) 시간 복잡도 내에 검사를 마칠 수 있도록 최적화했다.
