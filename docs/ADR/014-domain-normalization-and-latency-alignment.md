# [ADR-014] 정량 평가 무결성 확보를 위한 도메인 정규화 및 위상 동기화 파이프라인 구축

* **Status:** Accepted
* **Date:** 2026-07-28
* **Related Documents:** [evaluation_devlog.md](../devlogs/evaluation_devlog.md)

## 1. Context (배경)

벤치마크 평가를 위한 `evaluator.py` 가동 중, 평가 결과의 객관성을 훼손하는 여러 편향(Bias) 요인이 식별되었다.
1. **GT 도메인 불일치:** Slakh 데이터셋의 정답지(GT)가 물리적 주파수보다 1옥타브 높게 기보되어 있어, 정상 추론이 False Positive로 채점되었다[cite: 2].
2. **위상 지연 (Latency Shift):** E2E 평가 시 분리 모델(Demucs)을 거치면서 발생한 수십 ms의 오디오 지연이 채점 과정의 Onset 오차를 유발했다[cite: 2].
3. **다성부 페널티:** 정답 악보에 포함된 화음이나 더블 스탑 등이 단선율 모델 예측에 있어 부당한 감점 요소로 작용했다[cite: 2].

## 2. Decision (결정)

평가의 공정성을 위해 평가 모듈 내부의 데이터 전처리(Calibration) 로직을 다음과 같이 구성한다.

1. **도메인 정규화:** 정답지(GT) 주파수 배열을 데이터 로드 직후 `/ 2.0` 연산하여 물리 주파수 단위로 정규화한다.
2. **위상 지연 동기화 (Latency Alignment):** E2E 환경 평가 진입 전, 원본 베이스와 분리된 베이스 간의 상호상관도(Cross-correlation)를 계산해 위상을 물리적으로 동기화한다[cite: 2].
3. **GT 단선율 평탄화 (Monophonic Flattening):** 정답 데이터에 다성부가 존재할 경우, 서스테인을 보존하며 후입 노트가 앞 노트를 덮어쓰도록(Last-Note Priority) 절단하여 단선율화한다[cite: 2].

## 3. Rationale (의사결정 근거)

객관적인 벤치마크는 알고리즘의 순수한 추적 능력을 측정해야 한다. 데이터셋의 기보 관습이나 시스템적 위상 지연 등 외부 변인으로 인해 발생한 수학적 편차를 사전에 교정함으로써, 파이프라인의 실질적인 성능(Baseline)을 보다 정확하게 측정할 수 있는 환경을 조성한다.

## 4. Consequences (결과)

* **Positive:** 도메인 갭과 시간 오차를 보정하여 피치 및 리듬 추적 알고리즘의 성능이 평가 지표에 상대적으로 객관성 있게 반영될 것으로 기대된다.
* **Negative & Limitations:** 데이터셋 특성에 맞춘 보정 로직이 포함되었으므로, 다른 환경의 데이터셋(예: 실제 어쿠스틱 녹음 데이터)에 동일한 평가 프레임워크를 적용할 경우 정규화 파라미터를 다시 검토해야 하는 제약이 있다.
