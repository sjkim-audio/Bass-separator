# [ADR-013] 대용량 데이터셋 I/O 최적화를 위한 2-Pass 스트리밍 추출 아키텍처 채택

* **Status:** Accepted
* **Date:** 2026-07-28
* **Related Documents:** [dataset_spec_slakh2100.md](../devlogs/dataset_spec_slakh2100.md)

## 1. Context (배경)

약 100GB 규모의 Slakh2100 데이터셋을 단일 환경에서 전처리할 때 다음과 같은 물리적 제약이 존재했다.
1. 전체 데이터를 로컬 디스크에 압축 해제할 여유 스토리지 공간이 부족하다[cite: 2].
2. 대용량 오디오 배열을 메모리에 올려 파이썬 네이티브 라이브러리로 변환할 경우, 높은 확률로 메모리 초과 현상이 발생한다.

## 2. Decision (결정)

스토리지 및 메모리 병목을 피하기 위해, 압축 파일을 직접 해제하지 않고 처리하는 **2-Pass 스트리밍(On-the-fly) 추출 아키텍처**를 구축한다[cite: 2].

1. **Pass 1 (메타데이터 스캔):** 압축 파일 스트림을 순회하며 `metadata.yaml`만 스캔하여 렌더링 누락 및 다중 베이스 트랙을 제외한 유효 평가 모수를 확정한다[cite: 2].
2. **Pass 2 (타겟 추출 및 순차 변환):** 타겟 오디오 및 MIDI 파일만 임시 샌드박스로 추출하고, 파이썬 메모리를 거치지 않도록 `FFmpeg` 서브프로세스를 호출해 변환한 뒤 임시 파일을 즉시 삭제한다[cite: 2].

## 3. Rationale (의사결정 근거)

I/O 시간을 추가로 소모하여 압축 파일을 두 번 순회하는 방식은 연산 속도 측면에서 불리하지만, 제한된 로컬 스토리지 환경에서 작업을 수행하기 위해 시간 복잡도와 공간 복잡도를 타협(Trade-off)한 방법이다. 파이썬 생태계 내부를 우회하는 FFmpeg 델리게이션은 대용량 파일 변환 시 파이썬 프로세스의 과도한 메모리 할당 및 누수 위험을 구조적으로 억제한다.

## 4. Consequences (결과)

* **Positive:** 디스크 사용량을 제한적인 범위 내로 억제하면서 대규모 데이터의 선택적 가공이 가능해졌다.
* **Negative:** 백그라운드 프로세스 간의 파일 잠금(Lock) 현상에 의한 간헐적인 파일 삭제 지연 오류가 발생하여, 강제 쓰기 권한 할당 및 재시도 로직이 추가적으로 요구되었다.
