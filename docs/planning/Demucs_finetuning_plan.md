# Demucs Fine-Tuning & Dataset Strategy

본 문서는 베이스 음원 분리 알고리즘(htdemucs)의 성능 평가를 위한 커스텀 데이터셋 명세부터, 실제 모델의 성능 향상 및 치명적 망각(Catastrophic Forgetting) 방지를 위한 파인튜닝(Fine-tuning) 훈련 전략까지의 전체 파이프라인을 통합하여 기록합니다.

---

## 1. Evaluation Dataset (성능 평가용 데이터 명세)

모델의 베이스 분리 성능을 주법 및 음역대별로 정밀하게 검증하기 위해 통제된 환경에서 직접 녹음 및 제작된 베이스라인 테스트 음원입니다. 단순히 악기를 분리하는 것을 넘어, **베이스의 특정 주법 및 플레이 특성(음역대, 타격감 등)에 따른 분리 모델의 성능(SDR, SIR, SAR) 변화를 정량적/정성적으로 파악**하는 것이 목적입니다.

* **파일명**: `performance_test_demo(guitar + bass).wav`
* **길이**: 약 1분
* **트랙 구성**: 일렉트릭 기타 1 트랙 + 일렉트릭 베이스 1 트랙 (총 2 트랙)
* **음향적 특징**: 별도의 이펙팅(앰프 시뮬레이터, 드라이브, 공간계 등)을 거치지 않은 순수 DI(Direct Injection) 소스(Raw Recording)

### 1.1 음악적 구성 및 편곡 특징
* **코드 진행**: C Major 키(Key) 기준 `II - V - I - VI` (Dm7 - G7 - Cmaj7 - Am7) 진행
* **일렉트릭 기타 (Backing)**: 코드 반주(Comping) 위주로 연주. 하나의 코드 사이클마다 동일한 연주 소스를 반복하여 배경음을 상수로 통제하고 베이스 연주 변화에 따른 모델의 분리 성능을 정확히 측정합니다.

### 1.2 베이스 연주 섹션 구성 (Main Target)
두 프레이즈(코드 2바퀴) 단위로 연주 주법과 포지션이 지속적으로 변화합니다.

| 섹션 | 연주 스타일 | 테스트 목적 |
| :--- | :--- | :--- |
| **1. Root Notes** | 근음 위주의 단순 연주 | 저음역대 보존력 테스트 |
| **2. Standard Line** | 코드톤과 스케일을 활용한 일반적인 베이스 라인 | 다이내믹 및 선율 인식 테스트 |
| **3. High-register Solo** | 12프렛 부근에서 연주되는 고음역대 솔로 라인 | 기타 주파수와의 간섭 및 블리딩 방어력 테스트 |
| **4. Slap Bass** | 엄지와 검지를 활용한 슬랩 주법 | 강한 어택(Attack) 성분과 고주파 배음의 분리 및 왜곡(SAR) 테스트 |

## 2. Dataset Expansion & Augmentation (데이터셋 확장 및 증강)

현재의 통제된 DI 투트랙 환경을 넘어, 실전 믹싱 환경에 대응하고 파인튜닝 훈련의 효율을 극대화하기 위한 확장 전략입니다.

### 2.1 실전 환경 변수 추가 및 맞춤형 데이터 구축
* **Hard Case Testing**: 주파수 간섭이 심한 킥 드럼(Kick Drum) 트랙을 추가하여 간섭 제거(SIR) 능력을 테스트하고, 앰프 시뮬레이터, 오버드라이브, 공간계(Reverb/Delay)를 적용해 배음 왜곡 및 공간감 추가 상황에서의 분리 성능 저하율을 측정합니다.
* **약점 타겟팅 녹음**: 위 평가에서 발견된 취약점(예: 슬랩 주법의 아티팩트, 하이 포지션 기타 블리딩 등)을 집중적으로 보완하는 맞춤형 데이터셋을 신규 녹음합니다.
* **4-Stem 아키텍처 호환**: 일렉트릭 기타와의 간섭 제어 및 고음질 MR 생성을 위해 프로덕션 파이프라인은 최종적으로 4-Stem 아키텍처로 확정되었습니다. 멀티트랙이 없는 커스텀 데이터의 한계를 극복하기 위해 Zero-padding 기법을 활용하여 4개의 Stem 쌍으로 강제 구성합니다.

### 2.2 이원화된 데이터 증강 원칙 (Bifurcated Augmentation)
파인튜닝용 대규모 데이터셋 구축 시, 단순 무작위 믹싱이 유발하는 **'음악적 맥락 파괴(리듬 및 화성 불일치)'** 현상을 방지하기 위해 다음의 파이프라인을 적용합니다.

| 구분 | 대상 처리 | 원리 및 목적 |
| :--- | :--- | :--- |
| **전역적 증강<br>(Global)** | 조옮김(Pitch Shift), 속도 조절(Time Stretch) | **원리**: 분리된 개별 트랙(Bass, Other)에 반드시 동일한 비율의 피치/템포 변환을 동기화(Synchronize)하여 적용.<br>**목적**: 원본 DI 소스의 코드 진행과 타격 시점(Transient)을 완벽히 보존하며 실전 방어력을 기릅니다. |
| **독립적 증강<br>(Stem-specific)** | 트랙별 믹스 볼륨(Random Gain), 톤 왜곡(Hard Clipping) | **원리**: 음악의 화성과 리듬을 해치지 않는 선에서 각 트랙의 음향적 특성만 무작위 변형. 특히 베이스 트랙에 확률적으로 디스토션을 가하거나 볼륨을 낮춰 믹스.<br>**목적**: 특정 톤에 대한 과적합(Overfitting)을 방지하고, 하드 케이스 환경을 모사하여 강건성(Robustness)을 확보합니다. |

### 2.3 출력 규격 및 수학적 무결성
모든 증강 데이터는 음악 소스 분리 분야 표준인 **MusDB18 데이터셋 규격**으로 렌더링됩니다.
* **구조**: `train/`, `valid/`, `test/` 하위에 증강 버전 폴더를 생성하고 `bass.wav`, `other.wav`, `mixture.wav` 파일 포함.
* **무결성 보장**: 생성된 `mixture.wav`는 오디오 텐서 레벨에서 `bass.wav + other.wav`의 수학적 합산과 완벽히 일치하도록 설계되어, 모델의 손실 함수(Loss Function) 계산 시 위상(Phase) 오류가 발생하지 않도록 철저히 통제합니다.

## 3. Fine-Tuning Strategy & Training Plan (파인튜닝 훈련 계획)

### 3.1 Objective (파인튜닝 목표)
특정 장르나 특정 주법에만 국한된 전문가 모델을 만드는 것이 아닌, **어떤 환경의 오디오 소스에서도 베이스를 안정적으로 분리해내는 '범용 모델(General-purpose Model)'의 정밀도를 끌어올리는 것**이 최종 목표입니다. 

직접 구축한 하드 케이스 데이터셋으로 취약점을 보완하되, 모델이 기존에 학습한 넓은 음악적 범용성(치명적 망각, Catastrophic Forgetting)을 잃지 않도록 철저히 통제된 환경에서 학습을 진행합니다.

### 3.2 Core Strategies (치명적 망각 방지 핵심 전략)
범용성을 유지하며 성능을 끌어올리기 위해 PyTorch 학습 루프에 다음과 같은 3가지 안전장치를 도입합니다.

* **A. Data Rehearsal (데이터 믹스 훈련)**
  * 커스텀 증강 데이터셋에만 모델이 과적합되는 것을 방지합니다.
  * 기존의 광범위한 상업 음원이 포함된 공개 데이터셋(예: MusDB18)을 가져와, `[커스텀 데이터 30% + 범용 데이터 70%]`의 비율로 섞어 미니배치(Mini-batch)를 구성합니다. 모델은 새로운 약점을 극복하면서도 기존의 지식을 리허설(복습)하게 됩니다.
* **B. Layer Freezing (선택적 가중치 동결)**
  * Demucs 네트워크의 모든 층을 재학습시키면 기존 분리 체계가 붕괴할 위험이 있습니다.
  * 오디오의 보편적 음향 특징을 추출하는 앞단(Encoder)의 가중치는 완전히 동결(Freeze)하고, 베이스의 최종적인 질감을 복원하는 뒷단(Decoder)이나 병목(Bottleneck) 구간의 파라미터만 미세하게 업데이트하도록 학습 레이어를 분리합니다.
* **C. Low Learning Rate & Early Stopping (학습률 제어)**
  * 기존의 안정적인 가중치 텐서가 크게 요동치지 않도록 초기 모델 학습 시보다 현저히 낮은 초저도 학습률(Learning Rate)을 설정하여 점진적인 방향으로만 튜닝합니다.
  * 검증 데이터셋(Validation Set)의 SDR 지표가 하락하기 시작하면 즉각 학습을 중단(Early Stopping)하여 과적합을 원천 차단합니다.

### 3.3 Training Pipeline (진행 로직)
1. **데이터 로더 구성**: 커스텀 데이터와 범용 데이터를 혼합 출력하는 PyTorch `Dataset` 및 `DataLoader` 모듈 작성. (4-Stem 형식 유지를 위한 Zero-padding 로직 포함)
2. **모델 레이어 세팅**: `htdemucs` 사전 학습 가중치 로드 및 특정 레이어 `requires_grad = False` 처리.
3. **지표 트래킹**: Weights & Biases (W&B) 연동을 통해 에포크(Epoch)별 Loss 및 분리 지표(SDR, SIR, SAR) 실시간 시각화 모니터링.
